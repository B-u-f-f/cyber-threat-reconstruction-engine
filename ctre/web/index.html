What this tool does

A Windows intrusion leaves traces in more than one place. A file lands on disk, the filesystem records the change, and traffic leaves the machine. Those traces are usually examined with separate tools, so the link between them is easy to miss. CTRE reads three artifacts together, looks for timestamp tampering and data exfiltration, and lays everything on one timeline.

  1. 1

    Load the artifacts

    The $MFT is the NTFS master file table (one record per file, with its timestamps). The $UsnJrnl is the change journal, a running log the kernel keeps of every filesystem change. The .pcap is a network capture. Drop in any combination, or load the built-in sample case.

  2. 2

    Parse, read-only

    Each file is opened read-only and parsed defensively, so a malformed or hostile artifact is skipped instead of crashing the run. Timestamps are converted to a single UTC time base so disk and network events can be compared.

  3. 3

    Detect and correlate

    The detector compares the easily altered $MFT timestamps against the harder-to-forge $FILE_NAME times and against the change journal, flagging timestomping. The correlator looks for a large outbound transfer that lines up in time with a disk change.

  4. 4

    Review the timeline

    Findings, correlations, and every disk and network event appear on one timeline you can filter by source. Download the HTML report or the JSON to keep or share.

How to read the results

Timestomping rules

Windows stores two sets of timestamps for a file. The $STANDARD_INFORMATION (SI) times are what tools and users see, and they are easy to rewrite. The $FILE_NAME (FN) times and the change journal are maintained by the kernel and are harder to forge. The detector looks for disagreements between them.

RuleSeverityWhat it means
SI_BEFORE_FNHIGH The file's SI creation time is earlier than its FN creation time. A file cannot be created before its own name record, so the SI time was likely set into the past.
SI_BEFORE_JRNLHIGH The SI creation time is earlier than the journal's own record of the file being created. The journal cannot log a file before it exists.
ZERO_SUBSECONDMEDIUM Several SI timestamps have their sub-second digits zeroed. Many timestomping tools write whole-second times. (So do files from ZIP archives or FAT media, so treat this as a lead.)
NO_JRNL_FOR_CHANGEMEDIUM The SI modified time is newer than any journal entry for the file, i.e. a change the journal never recorded.
Exfiltration correlation

The correlator pairs a large outbound flow with a disk change that happened within the time window. On its own, neither is proof: a big upload can be legitimate, and files change constantly. Together, a file appearing or changing and then a transfer of similar timing to an external host is the pattern worth examining. CTRE reads only the size, timing, and destination of the transfer, never its contents.

Glossary
$MFT
NTFS master file table. One record per file, holding its attributes and timestamps.
$UsnJrnl:$J
The NTFS change journal, an append-only log of filesystem changes kept by the kernel.
Timestomping
Altering a file's timestamps to hide when it was created or changed, a common anti-forensic technique.
Flow
One network connection, summarized by its endpoints, ports, timing, and byte counts.
SNI
Server Name Indication, the hostname a client sends in the clear when starting a TLS connection.
Exfiltration
Moving data off a system, often the goal of an intrusion.
Scope and safety

CTRE works on copies of already-collected artifacts and never writes to them. It makes no network connections of its own. It does not read TLS keys from memory and does not decrypt traffic; that would be a general-purpose interception tool, so it is left out on purpose. This local server listens only on your own machine and deletes uploaded files when it stops.

Offline, read-only. Network findings use capture metadata only; no traffic is decrypted.
